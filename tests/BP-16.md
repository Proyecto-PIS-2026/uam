# BP-16: Restablecimiento de contraseña

La suite general está en `bp-16.spec.ts`. Los identificadores siguientes pertenecen
a BP-16; las dependencias conservan su propia numeración.

| Casos | Criterio | Comprobación |
| --- | --- | --- |
| CP-01, CP-02, CP-03 | CA-1 y CA-3 | Solicitar recuperación, comprobar el registro y visualizar la misma cuenta en Gestión de Usuarios después de recargar. Distinguir otra cuenta sin solicitud. |
| CP-04, CP-05, CP-06 | CA-2 | Cambiar usando la contraseña actual, cerrar sesión, rechazar la anterior e ingresar con la nueva. |
| CP-07, CP-08, CP-09 | CA-2: control técnico | Rechazar una contraseña actual incorrecta, conservar el hash y volver a ingresar con las credenciales originales. |

Cada grupo cubre, en orden, Operador, Productor y Administrador. La solicitud
utiliza el nombre de usuario; el inicio de sesión administrativo utiliza su correo
y el segundo factor real. Los cambios y solicitudes se realizan por la interfaz;
la base solo prepara cuentas, verifica persistencia y limpia los datos propios.

La suite comparte cuentas temporales y helpers con BP-16.2. El bloqueo de
`restablecimiento-contrasena-db.ts` conserva y restaura el valor original de la
configuración global. La limpieza incluye los avisos de estas solicitudes enviados
a otros administradores. BP-16.1 también crea su propio usuario, sin modificar las
credenciales ni las solicitudes de las cuentas de la seed.

## Ejecución

Preparar una base PostgreSQL exclusiva para pruebas con `npm run db:setup`,
utilizando esa base en `DATABASE_URL`. Iniciar la aplicación con la misma base y
configurar `PLAYWRIGHT_TEST_BASE_URL` con la URL del servidor. Usar las variables
de sesión y segundo factor habituales del proyecto; el workflow de CI documenta
la preparación del servidor y las migraciones.

Solo los nueve casos generales:

```sh
npx playwright test --project=chromium-bp16 --no-deps tests/bp-16.spec.ts
```

BP-16 y sus tres dependencias:

```sh
npx playwright test --project=chromium-bp16 --no-deps
```

El proyecto ejecuta con un worker y agrupa los cuatro archivos para evitar
interferencias con los casos de BP-16.2 que deshabilitan la configuración global.
`--no-deps` omite las suites ajenas al BP que preceden a este proyecto en la
ejecución completa de CI. El `webServer` general de Playwright prepara otros BP;
el servidor de la aplicación debe estar iniciado como se indicó arriba.

Las validaciones adicionales (confirmación, longitud, cancelación, acceso y
filtros) siguen en las suites de BP-16.1/16.2/16.3. No se consideran criterios
adicionales de la historia general.
